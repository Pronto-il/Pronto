# shared/components

## Purpose
Reusable UI components used across more than one feature (buttons, form fields, layout
primitives, etc.) — not feature-specific components, which live under their own
`features/*` folder.

## Responsibilities
- Generic, presentational building blocks with no feature-specific business logic.
- Consistent RTL/Hebrew-aware styling baseline shared across the app.

## Status
Stub only — no components yet. First components are added as needed starting
**Milestone 1 — Auth & user management** (`docs/architecture/implementation-plan.md`),
whenever a UI need is shared by more than one feature.
